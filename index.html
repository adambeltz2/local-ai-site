How the pieces fit together (what am I setting up?)
  1. Engine: Ollama. A program that runs on your computer, loads a model into memory and answers requests at http://localhost:11434. Everything below assumes Ollama. Nothing here needs the internet after the model is downloaded.
  2. Model. The file Ollama downloads, picked by the recommendation for your machine and task (ollama run <tag>).
  3. Settings. Mainly the context length: how much text the model can see at once. Ollama's default is small, and agent tools need much more.
  4. Tool. (Each recommendation shows your own version of this stack as a diagram under "Connect a tool".) The thing you actually use: a chat page (Open WebUI), an editor extension (Continue, Cline) or a terminal agent (opencode, Aider). The tool is optional for plain chat and required for working on code. Each tool is just a different front door to the same Ollama address, so you can try several with one model.

LM Studio is an alternative engine: it has its own app and model catalog, and tools can connect to it at http://localhost:1234/v1 instead of Ollama's address. llama.cpp is another. The model names and commands on this page are written for Ollama.

How the fit and speed estimates work

These are rough planning numbers, not benchmarks.

  • Memory needed is the model's footprint at about 8K context. Where a source gave one it is used; otherwise it is the Q4 weights size plus a KV-cache allowance (0.5 GB under 3 GB of weights, 1 GB under 8 GB, 1.5 GB above).
  • GPU: fits in VRAM with 0.5 GB reserved for the display and driver. GPU (tight): fits only if you use all of the VRAM. CPU offload: spills into system RAM (5 GB kept free for the OS unless a machine sets os_reserve_gb) and runs slower. CPU only: the machine has no usable GPU, so the whole model runs from system RAM. Too large: does not fit even with offload.
  • Est. tok/s assumes generation is memory-bandwidth bound: bandwidth divided by the bytes read per token, times 0.6 for real-world efficiency. For mixture-of-experts models only the active parameters count, then the result is halved as a conservative allowance for expert-routing overhead (an assumption, not a measurement). Offloaded layers are billed at system-RAM bandwidth. Prompt processing and your real runtime will differ, and very small models are still optimistic.
  • Task recommendations walk each task's quality-ranked list (in tasks.json) and pick the highest-ranked model that meets the task's speed target: 30 tok/s for editor autocomplete, 10 for chat, reasoning and documents, 8 for agents, vision and automation. "Higher quality, slower" is a better-ranked model that runs at 3+ tok/s but misses the target. "Faster option" is a lower-ranked model that fits your GPU and is at least 1.5x faster. Models that are not in Ollama are never recommended. The ranking itself is editorial judgment informed by the cited sources, with benchmark numbers quoted only where a source gave one.

Data is compiled from the sources above and may be out of date or wrong. These are estimates, not guarantees: real speed depends on your drivers, settings and other programs. Check the model card, license and Ollama tag before you download. A ? next to a license means it was not confirmed from a fetched source. Edit models.json, machines.json and tasks.json, then run python3 build.py.
